# 実験ログ — LoRA 暗黙オントロジー転移

各実装段階の「やったこと・結果・学び」の記録。設計の正本は `experiment-design.md`。
（数値・結論はその時点のもの。以後の段階もこのファイルに追記する）

---

## S1. 課題整理（対象タスクの選定）

- **やったこと**: アプリの LLM 使用箇所を棚卸しし、fine-tune 対象を検討。
- **結果**: 会話生成/フィードバックは FT 不向き（オープン・品質リスク）。**トピック抽出**
  （会話→概念グラフ JSON）が勝ち筋：狭い・構造化・頻出・データ自作可。根本課題は
  **タクソノミー未定義**（node_type/relation_type が自由文字列で毎回バラバラ）。
- **学び**: 「タクソノミーを明示定義する代わりに、一貫した例で暗黙的に学ばせる」が実験の核。

## S2. Langfuse セルフホスト + トレース収集

- **やったこと**: 公式 compose（6コンテナ）をポート調整して起動（web:3001）。完了セッション5件を
  本番プロンプト+Gemini で再実行し、Langfuse 計装 + JSONL 化（`collect_traces.py`）。
- **結果**: トレース5件記録。`DATABASE_URL` と POSTGRES_PASSWORD の不一致（P1000）で初回起動失敗
  → `.env.example` にハマりどころとして明記。
- **学び**: Gemini provider は **system-only プロンプトを拒否**（user メッセージ必須）— 以後3回踏んだ。

## S3. 型固定の効果検証（合成データ）

- **やったこと**: 多様トピックの合成会話 + 抽出で型の発散を観測 → 型を7種/6関係に固定した指示で再生成。
- **結果**: 5会話で node_type **22種 → 7種に収束**、relation 24種 → 6種。ただしプロンプト指示だけでは
  後日も語彙外（project/incorporates 等）が出た。
- **学び**: 型の一貫性はプロンプトだけでは守られない → 検証段/リンター/制約デコードが必要。

## S4. gold-editor（視覚的な gold 作成ツール）

- **やったこと**: 会話生成 → Gemini 下書き → Cytoscape でクリック編集 → gold 保存のミニ Web アプリ。
- **結果**: Cytoscape の CDN 読み込み失敗でノード非表示 → ローカル同梱・data(color) 方式・no-store で解決。
  DB の旧会話は participant 未割当で話者ラベルが壊れており、**会話は生成に一本化**。
- **学び**: 併せて editor 保存で current_summary が落ちるバグも後日発見・修正（S8）。

## S5. 実験設計・オントロジー定義

- **やったこと**: 設計書（仮説・3条件比較・評価4層）+ ドメインオントロジー2本
  （研究・制作系=SciERC/CoreSC 翻案、行動経験系=STARL 翻案）。共通7型・6関係・必須スロット・coverage 規則。
- **結果**: 「学習2ドメインに明示定義、評価3ドメインは未定義」= 転移測定の構図が確定。
- **学び**: 評価は JSON 妥当率を捨て（後段整形で吸収・修復不能率のみ記録）、粒度・一貫性を主役に。

## S6. 較正ラウンド（人間フィードバック → ルール化）

- **やったこと**: pending-001 と b2 バッチ（短い会話・応募者の出来3タイプ）を人間が全件検証。
- **結果**: gold 5件確定。フィードバックを都度オントロジー v0.1 にルール化：
  **主題ハブ必須／全ノード到達性／problem→行動は leads_to（動機づけ向き）／エッジの忠実性
  （会話に根拠のない因果は張らない）／成果物は part_of でなく leads_to**。
  忠実性違反も検出（draft が「月間20万PV**達成**」と捏造 — 会話では「目指す」）。
- **学び**: 「一貫させる→眺める→粗が見える→ルール化」の反復が gold 作りの本体。

## S7. few-shot 注入の効果

- **やったこと**: 人間検証済み gold を抽出プロンプトに few-shot（同族優先3例）で注入。
- **結果**: draft の lint 通過率 **0/4 → 4/6**（残りは要確認フラグのみ）。数字捏造も消失。
- **学び**: 例示は指示より強い。「暗黙オントロジー」仮説の in-context 版がすでに機能している
  （= 実験の few-shot 条件が強いベースラインになる見込み）。

## S8. 量産（学習用30件）+ 自動修正パス

- **やったこと**: ドメインを**オントロジー族**として6トピックに拡張（定義は2族のまま、held-out 不変）。
  b4=24件生成 → `review_assist.py`（較正ルールの自動適用: 非ハブaddresses反転・重複ペア・型スワップ、
  数字忠実性フラグ）→ 残りを手動検証。
- **結果**: 30件中 **自動で20件 clean、手動対応10件** → 全30件 lint clean。
  coverage 合計 319 covered / 59 weak / 14 gap（出来3タイプで健全に分散）。
- **学び**: 較正済みルールの大半は機械化できる。人手は「文脈が要る判断」
  （coverage の妥当性・欠落スロットの gap 化・無関係ノードの削除）に集中。

## S9. 人間の1割抜き取り検証

- **やったこと**: 30件から4件（13%）を人間が確認（b3-002 / b4-002 / b4-004 / b4-015）。
- **結果**: 重大不良なし。指摘3点を全体に反映しルール化：
  **チーム共通の慣行（Slack/定例MTG）はハブから uses**（役割からは本人固有の行動のみ）／
  **本人表記は「自分」**（アプリでユーザ自身の脳内グラフになるため。全30件で9箇所置換）／
  **エッジ節度**（並列 leads_to を代表に絞る。b4-004 は 24→17 エッジ）。
  b4-002 では役割スロット欠落（STARL必須違反）の見逃しも発覚 → 修正。
- **結果2**: 抜き取り4件は gold 保存され **gold 計9件**。バッチ30件は学習データとして採用。

## S10. 評価ハーネス + ものさしの検証 ✅

- **やったこと**: 依存ゼロの指標実装（`eval/metrics.py`）: 正規化（修復不能率）、層2 粒度・一貫性
  （ノード数分布/抽象ラベル率/重複率/孤立率/型付け一貫性）、層3 gold一致（曖昧マッチ node F1 /
  typed F1 / edge strict+relaxed）。類似は文字バイグラム Jaccard（将来 埋め込みに差し替え可）。
  壊した gold で判別力を検証（`eval/validate_metrics.py`、gold 9件）。
- **結果**: **各破壊が狙った指標だけを落とす**ことを確認：

| 条件 | nodeF1 | typedF1 | edge strict | edge relaxed | 抽象率 | ノード数 |
|---|---|---|---|---|---|---|
| self（gold vs gold） | 1.0 | 1.0 | 1.0 | 1.0 | 0.0 | 13.7 |
| C1 型シャッフル | 1.0 | **0.198** | 1.0 | 1.0 | 0.0 | 13.7 |
| C2 抽象ラベル置換40% | **0.626** | 0.626 | **0.362** | 0.362 | **0.374** | 13.7 |
| C3 ノード過分割 | **0.68**(P低下) | 0.68 | 1.0 | 1.0 | 0.0 | **26.6** |
| C4 関係シャッフル | 1.0 | 1.0 | **0.537** | **1.0** | 0.0 | 13.7 |

- **学び**: 指標の判別的妥当性OK（C1はtypedのみ・C4はstrictのみ落ち、直交性が確認できた）。
  これで「モデル比較で差が出たら指標のせいではなくモデルの差」と言える土台ができた。

## S11. 評価用 gold ✅（完成）

- **やったこと**: held-out 3ドメイン×6件=18件生成 → 自動修正パス → Claude 検証（進行中）。
- **観測**: 自動 clean は 5/18 と学習ドメイン(20/24)より大幅に低い。特に**志望動機**でハブ未到達が多発
  → ただし精査すると「背景→動機→将来」と**ハブへ収束する構造**で意味的には妥当。
  リントの連結性チェックを**無向の成分チェック**に緩和（「ハブから派生」は学習ドメインのスタイル指針として維持）。
- **学び**: 定義済みオントロジーから遠いドメインほど draft の構造が揺れる（遠い転移の難しさの傍証）。
- **完成（2026-07）**: Claude検証18/18 → **人間の全件レビュー完了 → 評価用 gold 18件確定**（志望動機6/失敗経験6/バイト6、
  coverage 191 covered / 32 weak / 9 gap）。人間レビューから得た追加ルール:
  志望動機は「背景→動機→将来」の**収束構造**＋アンカー統一／「貴社」「応募者」等の**面接語彙をラベルに使わない**／
  **causes の向き検算**（発見順の語りで逆転しやすい）／**最終ターンの取りこぼし確認**／
  ハブが「取り組み」なら施策は part_of 帰属／contradicts の正当例=語られた認識の食い違い（ev-008）。

## S12. Modal LoRA スモークテスト ✅

- **やったこと**: 検証済み30件 → SFT chat 形式（few-shot なし素プロンプト）→ Modal A10G で
  Qwen2.5-3B-Instruct + LoRA(r16, 4epoch)。
- **結果**: 1回目 **CUDA OOM**（seq8192・checkpointing無し）→ grad checkpointing + seq6144 +
  expandable_segments で解決。2回目成功: **loss 1.36→0.62**、アダプタ保存、生成は正しいスキーマ・
  concept 粒度の JSON（max_new_tokens=1500 での切り捨てで parse_ok=false になっただけ→3000に修正）。
- **学び**: 30件でも形式と粒度の流儀は学習される。配線（Modal/学習/保存/生成）は全て通った。
  費用は A10G 数十分（イメージビルド込み初回 ~30分）。

## S13a. 学習データ増量（30 → 120）✅

- **やったこと**: b5=90件生成（6ドメイン×出来3タイプ×few-shot）→ 自動修正パス（64/90 clean）
  → 判断が要る13件を手動検証（contradicts 8件は全て対比/トレードオフの誤用、正当例なし）
  → 全covered 13件は **coverage 審判**（較正済み基準を Gemini に代行、降格のみ適用）で 6件降格。
- **結果**: 学習セット **120件 / lint 120件clean**。トピック均等（19〜22件）、
  coverage 1397 covered / 184 weak / 59 gap。
- **学び**: 人手検証の大半が「自動修正 + LLM審判 + 少数の手動判断」に分解できた
  （90件中、真に手で直したのは13件）。面接語彙リンター（応募者/貴社）が新バッチでも即機能。

## S13c. 転移仮説の検証結果 ✅（2026-07）

3条件 × 評価gold 18件（near=失敗経験/バイト12・far=志望動機6）。指標は eval/README.md。

| 条件 | nodeF1(all) | typedF1(all) | nodeF1(far) | typedF1(far) | 修復不能 | N平均±std |
|---|---|---|---|---|---|---|
| zero | 0.236 | 0.111 | 0.255 | 0.086 | 3/18 | 10.7±2.3 |
| few  | 0.342 | 0.251 | **0.250** | 0.145 | 1/18 | 10.7±2.8 |
| lora | **0.388** | **0.273** | **0.388** | **0.228** | 1/18 | 13.8±4.2 |

ペア勝敗（lora vs few）: near nodeF1 8-0-4 / typedF1 6-1-5、far nodeF1 3-0-3 / typedF1 **4-1-1**。

**結論（部分的支持）**:
1. 全体順位は zero < few < lora（一貫）。120件の重み学習は in-context 3例を上回る。
2. **far（族の外）で few-shot はほぼ無力**: nodeF1 0.250 ≒ zero 0.255、型一貫性はむしろ低下(0.667)。
   学習ドメインの例が遠いドメインでは表面パターンへの誤アンカーになる。
   一方 LoRA は far でも nodeF1 0.388 を維持 — **「切り方の流儀」は in-context より重みの方が遠くまで運べる**。
3. 仮説の核心である**型付け（typedF1）は far のペア勝敗 4-1-1 で LoRA 優位** — 暗黙オントロジーの転移を支持。
4. **不支持だった予測**: 粒度の安定化（ノード数分散の縮小）は起きず、むしろ拡大（±4.2、far では 17±4.9 と過剰生成）。
5. 限界: far は n=6（小標本）、エッジF1 は全条件で ≤0.07（関係抽出は 3B には難、または gold のエッジが厳しい）、
   絶対性能は teacher (Gemini) 未計測のため相対位置が不明。
