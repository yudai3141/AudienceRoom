# 研究内容ドメイン オントロジー v0

学習ドメイン「研究内容」の gold を作るための定義書。SciERC（科学テキストの概念抽出スキーマ）と
CoreSC/DEO（研究談話の修辞構造）を面接用に翻案したもの。**型は共通7型を使い、本書は
「このドメインで何をどの型に入れるか」を定義する**。編集歓迎（v0）。

## 型マッピング

| ドメイン内容 | 型 | 良い label 例 | 悪い label 例 |
| --- | --- | --- | --- |
| 研究テーマ・主題 | concept | 「PTSD対話型エージェント」「若年層向け学習アプリUI改善」 | 「研究テーマ」 |
| ドメイン概念・専門用語 | concept | 「ACT-R理論」「半構造化インタビュー法」 | 「専門知識」 |
| 問題意識・先行研究の限界 | problem | 「トラウマ再喚起リスク」「情報過多による疲労感」 | 「課題」 |
| 限界・未検証な点 | problem | 「サンプル5名の統計的妥当性」 | 「弱み」 |
| 手法・アプローチ・工程 | method | 「グラフDBによる連想記憶」「ユーザーテスト（5名）」 | 「手法」「プロセス」 |
| **自分の貢献・工夫** | component | 「ダッシュボード形式による情報量削減」「スキーマ設計を主導」 | 「改善点」「私の役割」 |
| 成果・評価・数字 | result | 「タスク完了率20%向上・満足度4.5」 | 「効果」「成果」 |
| 学び・獲得スキル | result | 「本質的ニーズを見極める洞察力」 | 「学んだこと」 |
| 応用先・企業との接続 | goal | 「データに基づくUI/UX改善への応用」 | 「将来性」 |
| 研究の場・環境 | context | 「専門学校の卒業制作」「◯◯研究室」 | 「背景」 |

## 必須スロット（欠けたら gap ノードとして立てる）

1. 主題 ≥1（concept）
2. 問題意識 ≥1（problem）
3. 手法 ≥1（method）
4. 成果 or 評価 ≥1（result）— 語られなければ `label: 評価方法（未説明）` のような gap ノード
5. **自分の貢献 ≥1（component）** — 面接で最も突かれる。曖昧なら weak/gap を明示

## 粒度規則

- 束ねノード禁止: 「課題」「改善点」で複数概念を1ノードに圧縮しない。**会話で具体的に
  語られた概念ごと**に分ける。
- 逆に、一言の列挙（例: 通知過多・検索性・配色）は最重要の1〜2個だけノード化してよい。
- 目安 8〜15 ノード。判断基準は「面接官が深掘りの起点にできる単位か」。

## 典型関係パターン

```
method  --addresses--> problem      （手法が課題を解く）
method  --leads_to-->  result       （手法が成果を生む）
component --part_of--> method       （貢献・工夫は手法の一部）
method  --leads_to-->  method       （工程チェーン: ヒアリング→プロト→テスト は残す）
result  --leads_to-->  goal         （成果が応用へ繋がる）
problem --causes-->    problem      （課題の因果）
矛盾はすべて contradicts（残す。上書きしない）
```

## coverage 判定

- **covered**: 数字・固有名詞・理由まで具体的に語れた
- **weak**: 言及したが曖昧・詰まった・一言だけ
- **gap**: 名前しか出ていない／面接官に聞かれて答えられなかった／必須スロット欠落
- 全ノード covered の gold は原則疑う（詰まりのない面接は稀）
