experiments の正本。議論の経緯は experiments/README.md、gold 作成ツールは gold-editor/ を参照。

## 1. 目的・仮説

**仮説**: 少数ドメイン（2つ）だけ粒度・オントロジーを揃えた gold で小型モデルを LoRA SFT すると、
モデルは「揃え方」そのものを学習し、**未見ドメインの会話でも同じ粒度・構造で概念グラフを抽出できる**
（= 暗黙オントロジーの out-of-domain 転移）。

背景:
- 面接会話は話題が発散するため、ドメインごとにオントロジーを人手設計する GraphRAG 的アプローチが取りにくい。
- 型語彙の遵守は制約付きデコードで機械的に強制できるが、**粒度（ノードをどこで切るか）・概念の選択・
  関係の張り方は制約でエンコードできない**。ここが FT 仮説の主戦場。

副次目的: LoRA fine-tuning + セルフホスト（Modal）+ 監視（Langfuse）を一通り経験する。

---

## 2. 実験デザイン

| 要素 | 設計 |
| --- | --- |
| 学習ドメイン | **研究内容**（技術系）・**チーム開発経験**（行動系）の2つ |
| 評価ドメイン（held-out） | **志望動機・失敗経験・アルバイトで工夫したこと**（学習に一切出さない） |
| gold | 学習用 30〜50例、評価用 各ドメイン 5〜10例（評価用は特に丁寧に） |
| 比較条件 | ① zero-shot（同プロンプトの素の小型モデル）② few-shot（学習ドメインの gold 2例を in-context）③ LoRA FT |
| モデル | Qwen2.5-3B-Instruct 系（日本語可・Modal 1GPU で回る）。teacher/judge は Gemini/Claude |
| データ分割 | **会話単位**で train/eval を分ける（ターン単位はリーク） |

**読み方**: 未見ドメインで LoRA が few-shot に対し「型付け一貫性・ノード数分散・型付きノードF1・judge勝率」で
優位 → 仮説支持。差が無ければ「in-context で十分」——どちらでも学びとして成立。

## 3. gold 作成パイプライン

```
Gemini 出力（会話生成 + 概念グラフ下書き）
   ↓
Claude（Fable）による検証・修正   ← 基準は下記 v0。人間のフィードバックで随時改訂
   ↓
人間（本田）による最終検証        ← gold-editor で視覚確認・修正 → 保存
```

- Gemini の下書きは現状「改善の余地が大きい」前提。Claude 検証で底上げし、人間は最終判断に集中する。
- Claude の検証基準は**固定しない**。人間の判定とズレた点を随時基準に反映する（このファイルを更新）。

### Claude 検証基準 v0（改訂前提）

1. **label は具体概念**（固有名詞・専門用語・主張）。「課題」「効果」等の抽象カテゴリ語は不可 → node_type へ。
2. **ノード数 8〜15** を目安に、重要概念に絞る（会話の長さに応じて多少の増減は可）。
3. **重複・類似ノードの統合**（例:「組み合わせ」と「統合」は同一実体）。
4. node_type / relation_type は固定語彙（7種 / 6種）から。**同じ概念には常に同じ型**。
5. coverage は会話の実態を反映（詰まった=weak、名前だけ=gap。**全部 covered は疑う**）。
6. エッジは意味の通る関係のみ。孤立ノードを作らない。leads_to への逃げすぎに注意。
7. **忠実性**: 会話に出ていない概念を捏造しない。
8. current_summary は「面接で話せる状態にどれだけ近いか」を 2〜3 文で。

## 4. 評価

### 4.0 正規化（指標ではない）
- 出力形式は評価対象にしない（後段の整形で吸収できるため）。
- ハーネスは決定論的パーサ（コードブロック剥がし等）→ 最後の手段で LLM 修復（**構文のみ、意味は不変**と厳命・発動率をログ）。
- **修復不能率だけをサニティ統計として報告**（黙って捨てると生存者バイアス）。

### 4.1 層2: 粒度・一貫性（自動・仮説の主戦場）
| 指標 | 捉えるもの |
| --- | --- |
| ノード数の分布（平均・分散、8〜15帯域内率） | 粒度の安定性（FT で分散が縮むはず） |
| 抽象ラベル率（ブロックリスト + LLM 判定） | category-in-label 汚染 |
| ラベル長分布（gold 分布との距離） | 短すぎ=カテゴリ的 / 長すぎ=文章的 |
| グラフ内重複ノード率（埋め込み類似 > τ） | 過細分化 |
| 孤立ノード率・エッジ/ノード比 | 構造の健全さ |
| **型付け一貫性**（出力間で類似概念が同じ node_type を得る率） | 暗黙オントロジーの一貫性。ドメイン跨ぎで測ると転移の直接証拠 |

### 4.2 層3: gold 一致（自動・要 held-out gold）
- **ノード F1**: 埋め込み曖昧マッチ（cos > τ、τ は手動較正）で対応付け → P/R/F1
- **型付きノード F1**: マッチ + node_type 一致
- **エッジ F1**: strict（relation 一致）と relaxed（不問）を併記（小グラフでは strict が過酷なため）
- coverage 一致は参考値（主観が強い）

### 4.3 層4: LLM-judge（意味的品質）
- **ブラインドのペア比較**（絶対採点はブレる）: 条件を伏せ順序シャッフルで勝率
- 観点: 忠実性 / 重要点の網羅 / ノイズ少なさ / 粒度の適切さ
- **judge の妥当性検証**: 人間が 10 件程度ブラインド判定し judge との一致率を確認

### 4.4 方法論ノート
- 評価は temperature=0。ドメイン別内訳 + ブートストラップ CI で報告（n が小さいため過大主張しない）。
- **ものさしの検証を先に行う**: gold 自身に高得点、壊した gold（型シャッフル / ノード過分割 / 抽象ラベル置換）に
  低得点が出ることを確認してから本評価に進む。
